# Security Policy

## Supported version

Security fixes are applied to the latest code on the `main` branch. Older commits and forks may remain vulnerable and are not maintained releases.

## Reporting a vulnerability

Please do not disclose suspected vulnerabilities in a public issue, pull request, or discussion. Use GitHub's **Report a vulnerability** option in the repository Security tab. If private vulnerability reporting is unavailable, contact the maintainer through the profile linked from the repository and ask for a private reporting channel.

Include the affected path or feature, impact, reproduction steps, and any relevant sanitized logs. Do not attach real credentials, session cookies, student records, or private exam data. You should receive an acknowledgement when the report is reviewed; no response-time or remediation-time guarantee is made.

Client-side checks and allowlists are not security boundaries. Do not send secrets to this static portal; restricted operations must enforce authorization on a trusted server.
